# Студия 2D-роликов: роли

Одиннадцать ролей, каждая — отдельный агент с собственной инструкцией (`(private kit)/studio/<роль>.md`, копии в `.claude/agents/`).
**Продюсер — это основная сессия Claude**: она даёт роли брифы, показывает тебе хуки на согласование и не даёт ролям пропустить проверку.
Запуск: как обычно («сделай ролик про …»), Claude сам ведёт конвейер; отдельную роль можно позвать по имени
(«пусть script-critic разнесёт этот сценарий», «позови sound-designer»).

| Роль | За что отвечает | Что отдаёт |
|---|---|---|
| **showrunner** (шоураннер) | одна идея на ролик, зритель, обещание → развязка; судит черновики конкурентов | `BRIEF.md`; оценки и выбор |
| **researcher** (ресёрчер) | каждая цифра с источником и «что именно она измеряет», ловушки, безопасность, 3 угла | `FACTS.md` |
| **screenwriter** (сценарист) | 3 хука по разным формулам + тест из 5 вопросов, таблица битов, ре-хуки, развязка на 60–80 %, петля, реплики для озвучки | `SCRIPT.md` |
| **script-critic** (критик, адвокат зрителя) | читает как листающий зритель: тест 2 секунд, **тест пересказа одной фразой**, плотность фактов (≤ 6 на 55 с), петля, понятно ли без звука | ВЕРДИКТ + список правок |
| **director** (режиссёр-раскадровщик) | что видно на каждом слове: сцены на якорях слов, глагол в каждом бите, камера, плашки, переходы, кадр 0, петля | `STORYBOARD.md` + таблицы для кода |
| **art-director** (арт-директор) | свет, палитра с яркостью, глубина (параллакс), шрифты, ключевые картинки сцен, кадр 0 как обложка; ревью контрольных листов | `STYLE.md`; таблица замечаний |
| **sound-designer** (звукорежиссёр) | голос и ударения (переформулировать, проверить распознаванием), музыка по секциям и тишина перед развязкой, звуки на видимое событие, уровни | `spec.json`, таймлайн, микс |
| **animator** (аниматор) | сцены в Remotion по раскадровке и стилю, всё на словах таймлайна, tsc, линт, контрольные листы до чистоты | код + результаты проверок |
| **qa-editor** (монтажёр/ОТК) | полоски движения, один рендер через очередь, финальные проверки (×1.25, −14 LUFS, яркость, синхрон), подпись, отчёт | файлы + строки CHECKS |
| **publisher** (публикатор) | описание с ключевыми словами темы, ≤ 5 хештегов, обложка из кадра 0, слот выкладки (1–2 в день), какой вариант хука на какой аккаунт, журнал постов; сам ничего не постит | `captions.json`, план и чек-лист перед публикацией |
| **analyst** (аналитик) | через 48 ч: «посмотрели / пролистали», среднее время, досмотр, сохранения, пересылки; `statlog.py`; меняет одну переменную; пишет урок в `rules/HOOKS.md` §9 | памятка из 5 строк + урок |

## Конвейер одного ролика
1. Идея → **showrunner** пишет бриф: ролик в одной фразе без «и», зритель, обещание и слово-развязка.
2. **researcher** собирает факты с источниками (не больше 10 строк).
3. Три **screenwriter** пишут три сценария по разным формулам хука; каждого разбирает **script-critic**; **showrunner** выбирает и склеивает лучшее;
   критик проверяет ещё раз (до 2 кругов). → Таблица хуков приходит **тебе на согласование** (гейт 1).
4. **director** делает раскадровку, **art-director** — стиль; **sound-designer** делает озвучку, проверяет её распознаванием и хук-гейт.
5. **animator** строит сцены, гоняет tsc, линт и контрольные листы; **art-director** смотрит листы (гейт 2).
6. **qa-editor** рендерит один раз, прогоняет финальные проверки (гейт 3), пишет подпись и отчёт. Продюсер отдаёт тебе файл и цифры.
7. **publisher** готовит описание, обложку, слот и раскладку вариантов хука по аккаунтам; **публикуешь ты**. Через 48 часов **analyst** снимает цифры и записывает урок.

**Два хука на один ролик:** в `spec.json` блок `"variants": {"B": {"h1": "…"}}`, затем `audio.py story1 --variant B` даёт второй микс и таймлайн из того же кэша голоса (`engine/README.md`). Вторая композиция рендерит те же сцены с другим хуком; варианты уходят на разные аккаунты или дни.

Предпродакшен (бриф → согласованный сценарий) идёт параллельно, как воркфлоу `.claude/workflows/studio-preprod.js`; производство — последовательно,
один аниматор на файлы и один рендер на сессию.

## Что это исправляет (из первых роликов)
- «Суть ролика плохо понятна» — в 51-секундном ролике было 10 фактов. Теперь: бриф одной фразой, тест пересказа у критика, лимит ≤ 6 фактов.
- Неверные ударения — знаки ударения коверкали гласные у голоса; звукорежиссёр переформулирует и проверяет распознаванием.
- Музыка «подлагивала» — она качалась под каждый слог; движок теперь приглушает музыку плавно (исправлено 2026-11-03).
- Кадр 0 закрывала рука — режиссёр описывает кадр 0 как обложку, арт-директор проверяет его в размере телефона.

## Ниши: пробовать несколько, гибко
Ниша — это папка `niches/<slug>/` с одним файлом `NICHE.md` (шаблон `(private kit)/studio/NICHE-TEMPLATE.md`): обещание канала одной фразой,
зритель, язык, формат и подходящие формулы хука, узнаваемый визуальный ход, голос и музыка, запреты, ключевые слова, аккаунт и ритм, таблица
результатов. **Все роли читают его первым**, поэтому смена ниши — это другая папка, а не другие инструкции. Старт: `python tools/new_niche.py <slug>`,
потом бриф ниши может набросать showrunner («showrunner, заполни NICHE.md для …»), каждый ролик — `new_project.py <template> niches/<slug>/01-<ролик>`.
Проба ниш: 2–3 ниши параллельно, по 4–6 роликов в каждой за две недели, одинаковый ритм выкладки, у каждой свой аккаунт. Через 48 часов после
каждого поста analyst заполняет `stats.csv` ниши, сравнивает только внутри ниши по медианам; после 4–6 постов — решение: удвоить лучшую,
остановить худшую, среднюю развернуть (тот же вид, новое обещание). Уроки хуков пишутся в общие правила, стиль остаётся в нише.

Файлы-передачи в папке проекта: `BRIEF.md → FACTS.md → SCRIPT.md → STORYBOARD.md → STYLE.md → story1/spec.json → src/timeline1.json → src/*.tsx → out/`.
