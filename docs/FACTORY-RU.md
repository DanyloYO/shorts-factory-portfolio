## 2. Что из этого следует для ролика
1. **Ролик живёт 3 секунды.** Для большинства зрителей весь ролик — это хук. Первый кадр уже самый интересный, без логотипа и заставки; движение в первые 0.5 с; надпись 1–5 слов в верхней трети; звуковой удар или тишина на 0–0.5 с.
2. **Досмотр важнее длины.** 20–45 с, которые досматривают, бьют 90 с, которые бросают. Длиннее минуты только когда каждый бит держит (и только там деньги TikTok).
3. **Петля и развязка.** Хук обещает одно, развязка на 60–80 % отвечает теми же словами, последняя фраза возвращает к первой, обрыв сразу после ответа без концовки.
4. **Одна мысль на ролик.** Это главный вывод и из исследования, и из нашего математического ролика (14 фактов за 51 с = «суть непонятна»).
5. **Оригинальность теперь правило допуска, а не нюанс.** Серии можно, одинаковый шаблон с подменой фактов нельзя. Каждому ролику свой взгляд, свой сюжет, свой визуальный ход.
6. **Делиться и сохранять.** Факт, который хочется переслать другу, сильнее лайка; просить лайк/подписку в ролике запрещено лентой.
7. **Поиск.** Ключевые слова темы звучат в голосе и стоят в субтитрах и описании, ≤ 5 хештегов.
8. **Ритм выпуска.** 2–5 в неделю стабильно, 1–2 в день максимум, новый аккаунт прогревать 2–3 дня; «сто проходных дают меньше, чем двадцать сильных».

## 3. Как это реализовать по ролям
Текущая студия (девять ролей, `docs/STUDIO-RU.md`) закрывает производство. Исследование добавляет три вещи: **кто решает**, **что меряем** и **как учимся**.

| Роль | Что делает в фабрике | Решение / гейт |
|---|---|---|
| **Ты (продюсер)** | выбираешь ниши и темы недели, правишь хук и последнюю фразу своей рукой, нажимаешь «опубликовать» | темы и хук никогда не выбирает агент (все разборы провалов сходятся на этом) |
| showrunner | одна мысль на ролик, бриф, судит черновики | бриф одной фразой без «и» |
| researcher | факты с источниками | ни одной цифры без источника |
| screenwriter | 3 хука по разным формулам, биты, петля | хук ≤ 2 с, читается без звука, предвещает развязку |
| script-critic | адвокат зрителя: тест 2 секунд, пересказ одной фразой, ≤ 6 фактов | **право вето**, дедлайн его не перебивает |
| director, art-director | раскадровка на словах озвучки, свет и палитра, кадр 0 как обложка | кадр 0 читается при 360 px |
| sound-designer | голос, проверка распознаванием, тишина перед развязкой, удар на каждом ре-хуке | хук-гейт по замеру |
| animator | сцены, tsc, линт, контрольные листы | линт чистый |
| qa-editor | один рендер, ×1.25, −14 LUFS, яркость, синхрон, подпись | файл с провалом не выходит |
| **publisher (новая)** | заголовок и описание с ключевыми словами, обложка из кадра 0, ≤ 5 хештегов, расписание 1–2/день, разные варианты хука на разные аккаунты, никогда один файл на два аккаунта | ты подтверждаешь публикацию |
| **analyst (новая, можно совместить с publisher)** | через 48 ч: «посмотрели / пролистали», среднее время, досмотр, сохранения, пересылки; меняет **одну** переменную (обычно хук); пишет урок в `rules/HOOKS.md` §9 | правило формул меняется только когда паттерн повторился в ≥ 3 роликах |

Как делать A/B хуков (ни одна платформа не даёт нативного теста): одно и то же тело ролика, 2–3 варианта первых 2 секунд, выкладка в одно время дня, сравнение по «посмотрели / пролистали» и удержанию на 3 с через 24–48 ч. Наш движок это умеет дёшево: хук — отдельный сегмент в `spec.json`, остальное кэшируется.

## 4. Неделя фабрики (один человек + агенты)
1. **Понедельник, 1 час:** ты выбираешь 6 тем на неделю в одной нише; showrunner пишет 6 брифов; researcher собирает факты параллельно.
2. **Вторник:** воркфлоу предпродакшена на все 6 (три сценариста → критики → судья → правки). Тебе приходят 6 таблиц хуков одним сообщением; правишь хуки сам.
3. **Среда–пятница:** производство по 1–2 ролика в день (звук → сцены → рендер → проверки). Каждый ролик получает 2 варианта хука.
4. **Выкладка:** 1 ролик в день, в одно время; второй вариант хука на второй аккаунт или через день.
5. **Через 48 ч:** analyst снимает цифры, через `tools/statlog.py` пишет урок; на следующей неделе двойной упор на выигравшую формулу.
Себестоимость: при edge-tts и синтезе музыки ролик стоит центы в API; ElevenLabs добавляет качество голоса, которое сейчас самое слабое звено.

## 4а. Несколько ниш сразу
Ниша живёт в `niches/<slug>/NICHE.md` (обещание, зритель, язык, формат, визуальный ход, голос, запреты, ключевые слова, аккаунт); роли читают его
первым, так что одна студия ведёт несколько ниш без переписывания инструкций. Проба: 2–3 ниши × 4–6 роликов за две недели, свой аккаунт у каждой,
одинаковый ритм; сравнение только внутри ниши по медианам; затем удвоить лучшую, остановить худшую, развернуть среднюю. Из раздела 1а: ниша должна
иметь свой узнаваемый ход, иначе через год её скопируют и рост встанет.

## 5. Что сделать первым
1. Добавить роли `publisher` и `analyst` (или одну роль с двумя режимами) и шаблон `captions.json` с полем «ключевые слова темы».
2. Сделать режим «2 хука на ролик» в воркфлоу и в движке (два `spec.json` с разным первым сегментом, одна композиция).
3. Пересобрать математику как v3 через студию и выложить её как первый замер: это даст первую строку в журнале уроков.
